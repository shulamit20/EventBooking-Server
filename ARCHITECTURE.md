# EventBooking — Clean Architecture

## The rule

Dependencies point **inward only**. `Core` is the centre and depends on nothing.

```
        ┌──────────────────────────────────────────┐
        │                  API                     │  Controllers, Middleware,
        │   (EventBooking.API)                      │  Program.cs, auth wiring
        │   ┌──────────────────────────────────┐   │
        │   │            Service               │   │  Business logic, validation,
        │   │     (EventBooking.Service)        │   │  the booking/concurrency flow
        │   │   ┌──────────────────────────┐   │   │
        │   │   │          Data            │   │   │  DbContext, Repositories,
        │   │   │    (EventBooking.Data)    │   │   │  Fluent API configs, Migrations
        │   │   │   ┌──────────────────┐   │   │   │
        │   │   │   │      Core        │   │   │   │  Entities, Enums, DTOs,
        │   │   │   │ (EventBooking.   │   │   │   │  Interfaces (contracts).
        │   │   │   │      Core)       │   │   │   │  NO external packages.
        │   │   │   └──────────────────┘   │   │   │
        │   │   └──────────────────────────┘   │   │
        │   └──────────────────────────────────┘   │
        └──────────────────────────────────────────┘
```

Arrows (project references):

- `Core`     → (nothing)
- `Data`     → `Core`
- `Service`  → `Core`
- `API`      → `Service`, `Core`, and `Data` **only** to register implementations in `Program.cs`
- `Tests`    → `Service`, `Core`, `Data`

Why it matters: if `Core` referenced EF Core, the domain would be chained to a database technology. Keeping `Core` clean means Service and its tests never touch a real database — they talk to interfaces.

## What lives where

### EventBooking.Core  (the contracts + the domain)
```
Entities/            Venue, Hall, HallSlot, User, Booking, ExtraService, BookingExtraService
Enums/               ShiftType, SlotStatus, BookingStatus, UserRole
DTOs/
  Requests/          CreateBookingRequest, RegisterRequest, LoginRequest, ...
  Responses/         BookingResponse, HallSlotResponse, AuthResponse, PagedResult<T>, ...
Interfaces/
  Repositories/      IHallSlotRepository, IBookingRepository, IUserRepository, IUnitOfWork
  Services/          IBookingService, IAuthService, IHallService, ...
Common/              Result, Result<T>, ResultStatus (Ok / NotFound / Conflict / Invalid)
```
No `using Microsoft.EntityFrameworkCore` anywhere in this project.

### EventBooking.Data  (all persistence — "the data is in DATA")
```
AppDbContext.cs               DbSet<T> per entity; SaveChangesAsync override (bump concurrency token)
Configurations/               IEntityTypeConfiguration<T> — keys, relationships, decimal precision,
                              BookingExtraService composite key, concurrency token
Repositories/                 HallSlotRepository, BookingRepository, UserRepository
                              -> implement the Core interfaces
                              -> the ONLY place LINQ / Include / AsNoTracking / Skip-Take is written
Migrations/                   generated by dotnet ef
Seed/                         DbSeeder — venues, halls, slots, extra services, demo users
DependencyInjection.cs        AddDataLayer(this IServiceCollection, IConfiguration) extension
```
Controllers never see this project's types. Services see only the interfaces (which live in Core).

### EventBooking.Service  (business logic)
```
Services/                     BookingService, AuthService, HallService
                              -> depend on Core interfaces via constructor injection
                              -> business/state validation lives here, not in controllers
                              -> BookingService owns the "check + save in one transaction,
                                 catch DbUpdateConcurrencyException -> Result.Conflict" flow
Mapping/                      AutoMapper Profile classes (entity <-> DTO)
Auth/                         password hashing, JWT token generation
DependencyInjection.cs        AddServiceLayer(this IServiceCollection, IConfiguration) extension
```
No `new BookingRepository(...)`. No `DbContext`. Only interfaces.

### EventBooking.API  (the edge)
```
Controllers/                  thin: bind -> ModelState -> call service -> map Result to HTTP status
Middleware/                   ErrorHandlingMiddleware (uniform JSON), CorrelationIdMiddleware
Program.cs                    pipeline order (errors -> auth -> authz), calls AddDataLayer()
                              + AddServiceLayer(), JWT config, Swagger, NLog
appsettings.json              safe defaults only
appsettings.Development.json  local overrides (still no secrets -> User Secrets)
nlog.config                   log targets and rules
```

### EventBooking.Tests
```
Services/                     BookingServiceTests (success + rejected), AuthServiceTests
                              -> repositories mocked with Moq
Concurrency/                  two real AppDbContext instances, same HallSlot, second SaveChanges throws
```

## One request, end to end (booking a slot)

```
POST /api/bookings
  │
  ▼
BookingsController                       [API]      binds CreateBookingRequest, checks ModelState,
  │                                                 passes CancellationToken
  ▼
IBookingService.CreateAsync(...)         [Core interface -> Service impl]
  │   - loads the HallSlot via IHallSlotRepository
  │   - business check: slot Available? no active booking?
  │   - creates Booking, marks slot Booked
  │   - SaveChangesAsync  ── DbUpdateConcurrencyException ──► return Result.Conflict
  ▼
IHallSlotRepository / IBookingRepository [Core interface -> Data impl]
  │   - EF Core, AppDbContext, the concurrency token in the WHERE clause
  ▼
Database
```

Controller then maps `Result`:
`Ok` → 201 + Location · `Invalid` → 400 · `NotFound` → 404 · `Conflict` → **409**.
